# 选择 Python 或迁移到 Go

Python 后端进入 BUG 维护阶段，不再增加新功能。新功能在 [Mx-Panel](https://github.com/Angasky/Mx-Panel) 的 Go 后端开发。

## 一次性公告

旧版更新到包含本功能的版本后，管理员登录时会看到公告。阅读满 5 秒才能点击“我已知晓”；服务端也验证等待时间。确认记录写入 `backend-choice.json`，同一面板换浏览器或重新登录不会重复显示。确认公告不等于同意迁移。

## 设置中的两种选择

- **继续使用 Python 后端**：保存选择，不下载或切换服务；以后仍可选择迁移。
- **一键迁移到 Go 后端**：核对管理员账号、密码并确认后执行。当前固定目标为 `go-v0.1.5` 预览版，不自动追随未验证的新版本。

自动迁移适用于 root 运行的 Linux / systemd、amd64 或 arm64，以及原安装器生成的 Nginx HTTPS 转发。HTTP 部署请先启用 HTTPS。自定义数据路径、外部订阅文件、已有 Go 安装或正在运行的远程节点任务会阻止自动迁移并提示原因。

Nginx 配置通过 `nginx -T` 自动识别实际生效且转发到旧后端 62577 端口的文件，支持 `conf.d`、`sites-enabled` 和自定义 include 路径。多个匹配文件会提示人工核对，不会任意选择。备份中的 `nginx-path.txt` 记录实际配置路径，手动恢复时请以该路径为准。

## 迁移过程

1. 下载对应架构的发布包，校验 SHA256、文件清单、文件类型及架构，检查旧数据兼容性。
2. 停止 Python，备份完整程序目录、订阅文件、账号和 Nginx 配置到 `/var/backups/mx-panel/python-to-go-*`，备份目录仅 root 可访问。
3. 禁用旧服务，安装 Go 并执行健康检查。原 Nginx 转发由 `127.0.0.1:62577` 切换到 `127.0.0.1:62578`，保留访问域名、HTTPS 证书及订阅地址。
4. 完成后刷新网页，用原账号重新登录。迁移期间网页短暂中断；关闭浏览器不影响独立 systemd 任务。

检测到安装或转发切换失败时，会停止 Go、恢复备份和旧转发并尝试重新启动 Python。恢复失败会明确记录，不会声称迁移成功，也不会自动重复执行。恢复时保留的 `.failed-python-to-go-*` 目录用于排查，不会立即删除。

## 排查与手动恢复

正常迁移失败并恢复 Python 后，可在设置页查看原因和备份位置。任务日志可在服务器执行 `journalctl -u 'mxioc-backend-migration-*'` 查看。突然断电、进程被强制杀死或磁盘损坏可能需要手动恢复；勿让两个后端同时写同一套数据。

如自动恢复未完成：先停止 Go 服务，核对备份中 `root/`、`subscribe/`、`auth.json`、`nginx.conf` 的完整性，再由管理员恢复至原位置，检查 `nginx -t`，重新加载 Nginx 并启动 `mxioc-rule-manager.service`。确认恢复后再修正 `backend-choice.json` 中的迁移状态。备份包含账号哈希和远程服务器凭据，请勿上传或公开分享。

## 验证边界

已验证公告与选择交互、接口鉴权与来源检查、安装包校验、隔离环境中的成功切换及故障恢复；公开发布包也通过 Python 数据和凭据兼容检查。测试不会切换当前服务器的生产服务。实际服务器仍需满足上述 systemd、Nginx、HTTPS 和磁盘条件。
